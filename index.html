Diagnosing and Fixing Capability Imbalance in Multi-Teacher On-Policy Distillation

Even with perfect domain routing, multi-teacher OPD loses capability because domains compete for one shared optimization budget.Open-MOPD reduces the integration gap from 3.50 to 0.31 points.

Anonymous authors

Paper under double-blind review.

SmolLM3-3B-Base · Math · Code · Instruction Following

arXiv Code Models

Math, code, and instruction-following experts can each gain capability through reinforcement learning, yet their strengths do not simply add up when all three teachers update one shared student. Even with correct hard routing by known domain labels, Naive M-OPD remains below the per-domain RouteOPD reference, with the largest deficit on short instruction-following responses. Open-MOPD traces this integration gap to three measurable optimization-budget problems: realized gradient-token share, the moving teacher–student gap, and stale rewards during repeated inner updates.

Method: control the shared student’s optimization budget

In M-OPD, the student first samples its own rollout, and a known domain label routes each trajectory to one frozen teacher. Experiments use SmolLM3-3B-Base, three domain teachers, top-k=16, and K=4 updates per rollout batch.

The teacher scores states visited by the student

At each visited state \(s_t\), the student keeps only the top-k tokens it actually considers. The routed teacher–student log-probability difference becomes a dense token reward:

\[\begin{aligned} S_t &= \operatorname{TopK}\!\left(\pi_\theta(\cdot\mid s_t)\right), \qquad k=16,\\ \delta_t(v) &= \operatorname{sg}\!\left[\log\pi_{\phi_{d(x)}}(v\mid s_t)-\log\pi_\theta(v\mid s_t)\right],\\ r_t(v) &= \delta_t(v)\,\tilde\pi_\theta(v\mid s_t). \end{aligned}\]

The teacher never needs to generate a demonstration; it turns preferences on the student’s current trajectory into a reward for PPO.

The real budget is not the prompt count

The effective update strength for domain \(d\) depends on both its realized token volume and the remaining teacher–student gap:

\[s_d^{\mathrm{tok}}=\frac{n_dL_d}{\sum_j n_jL_j},\qquad B_d\propto s_d^{\mathrm{tok}}\,\bar m_d,\qquad \bar m_d=\mathbb E|r_t|.\]

Uniform prompt sampling therefore does not guarantee an equal optimization budget across domains.

Token-share balancing

First, reweight the realized token share so that each domain receives one third of the token updates:

\[w_d^{\mathrm{share}}=\frac{g_d^*}{s_d^{\mathrm{tok}}},\qquad g^*=\left(\tfrac13,\tfrac13,\tfrac13\right).\]

This directly corrects the response-length bias: short IF responses are no longer systematically ignored because they contribute fewer tokens.

Gap-following allocation

Next, move budget toward domains with a larger teacher–student gap still left to close:

\[\begin{aligned} \tilde w_d &= w_d^{\mathrm{share}}\operatorname{Clamp}\!\left(\left(\frac{m_d}{m_{\mathrm{ref}}}\right)^\alpha,0.05,20\right),\\ w_d^{\mathrm{gap}} &= \frac{\tilde w_d}{\sum_j \tilde w_j s_j^{\mathrm{tok}}}, \qquad \alpha=1. \end{aligned}\]

The final normalization keeps the batch loss scale fixed. As gaps shrink at different rates, the weights move with them; reversing the direction collapses at step 74.

Reward refresh

Finally, recompute the student-dependent reward before every inner update while caching the frozen teacher log-probabilities once:

\[r_t^{(k)}(v)=\delta_t^{(k)}(v)\,\tilde\pi_\theta^{(k)}(v\mid s_t).\]

No additional teacher forward is required. The fix removes student-term staleness, but does not resample the rollout.

Diagnosis: three pieces of evidence for budget imbalance

The paper tests routed-teacher disagreement first, then measures token share, moving gaps, and reward staleness. Each axis maps to one fix above.

Teacher disagreement is measurable, but not the bottleneck

\[c_t=\max_d\log\pi_{\phi_d}(y_t\mid s_t)-\min_d\log\pi_{\phi_d}(y_t\mid s_t)\]

Mean disagreement = 0.126 nat; only 0.62% of tokens have \(c_t>1\) (3.9% on IF). Masking or consensus lowers total score by −0.52 to −0.83.

Prompt share is not token share

Prompt share: 39.8 / 39.8 / 20.3%; gradient-token share: 49.7 / 49.3 / 0.99% (Math / Code / IF). Math/Code responses are ≈ 10,500 tokens; IF is ≈ 409 tokens. IF needs about 33.6× oversampling to get one-third of the token budget.

Moving gaps and stale rewards

After flattening token share, IF budget falls from 48.7% → ~9% in about 25 steps; Code rises from 39.6% → 63.8%. Rollout reuse makes rewards stale: rollout-current KL is 0.059 at K=4 and 0.216 at K=32; clipped-token fraction reaches 0.86.

Results: 3.50 points → 0.31

Open-MOPD is one shared student; RouteOPD and RouteRL are domain-routed, non-deployable references. Recovery is RouteRL headroom recovery, not accuracy.
