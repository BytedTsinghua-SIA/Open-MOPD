# OpenOPD Verifier

The verifier scores rollout parquet files. Keep the public entrypoint narrow:

```bash
python -m evals.verifier.score \
  --rollout /path/to/*_rollouts*.parquet \
  --data-dir /path/to/benchmark-data/parquet \
  --details-dir /path/to/details \
  --output /path/to/scores.json
```

`score.py` is the only scoring entrypoint. It parses CLI args, reads rollout
parquet files, groups rows by `dataset`, dispatches to the appropriate scorer,
and writes aggregate JSON.

## Layout

```text
evals/verifier/
  score.py                  # only scoring entrypoint
  requirements.txt
  README.md

  score_functions/
    math/                   # math-answer benchmarks
      aime.py
    code/                   # code execution benchmarks
      evalplus.py
      evalplus_extract.py
      livecodebench.py
      livecodebench_official.py
      livecodebench_parallel.py
      livecodebench_subsets.py
    instruction_following/  # IFEval and IFBench
      common.py
      ifeval.py
      ifbench.py
      google_ifeval/
    common/                 # shared verifier utilities
      behavior.py
      utils.py

  scripts/
    manage_third_party.py

  third_party/
    repos.lock.json         # optional local lock; ModelMerging lock is fallback
    patches/
    repos/                  # local checkouts generated by manage_third_party.py

```

## Scoring Outputs

Each dataset result includes:

- `official`: score divided by the full official dataset size.
- `live`: score divided by rows/problems present in the provided rollout files.
- `official_extra`: scorer-specific metadata and detail-file paths.
- behavior counters for truncation and repetition.

For complete rollouts, `official` and `live` usually match. For partial
rollouts, use `live` to inspect only submitted rows.

Instruction-following scoring strips `<think>...</think>` blocks before calling
the official evaluator.

## LiveCodeBench

LiveCodeBench uses the official runner and defaults to two-level parallelism:

```text
--lcb-process-workers 160
--lcb-worker-concurrency 24
```

The outer process count is capped by the number of LCB problems in the current
batch. Each outer process asks the official evaluator to use 24-way internal
concurrency.

Useful flags:

```bash
--lcb-lm-style CodeQwenInstruct
--lcb-timeout 6
--lcb-subsets v5,v6
```

Use `--lcb-subsets v5,v6` when the rollout was generated from
`livecodebench_full` but should only be scored on V5 and V6. The subset filter
matches question ids from `--data-dir/livecodebench_v5.parquet` and
`--data-dir/livecodebench_v6.parquet`.

## Third-Party Repos

The verifier may need local checkouts of official scorers:

```bash
proxychains python -m evals.verifier.scripts.manage_third_party sync --repo livecodebench
python -m evals.verifier.scripts.manage_third_party apply-patches --repo livecodebench

proxychains python -m evals.verifier.scripts.manage_third_party sync --repo ifbench
python -m evals.verifier.scripts.manage_third_party apply-patches --repo ifbench
```

`manage_third_party.py` reads `evals/verifier/third_party/repos.lock.json` when
present and falls back to the ModelMerging lockfile. `third_party/repos/` is a
generated checkout area and can be recreated from the lockfile.
